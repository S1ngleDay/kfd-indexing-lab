# Ускорь индексацию

Подборка доступных товаров по рекомендациям с учётом исключений и повторений

```bash
./gradlew test
```

Основная функция — [ProductSelection.kt](src/main/kotlin/lab2/ProductSelection.kt).
Она использует [ProductSelector.kt](src/main/kotlin/lab2/ProductSelector.kt).

Каталог преобразуется в индекс `id → Product` через `associateBy`, исключения —
в `HashSet`. Это убирает повторный линейный поиск по каталогу и исключениям.
Идентификаторы уникальны в каталоге, поэтому `associateBy` подходит.
Ключ `Long` неизменяем и сравнивается по значению.

Рекомендации обходятся по порядку. Неизвестные, исключённые и недоступные товары
пропускаются. Множество добавленных идентификаторов убирает повторы.
Возвращаются исходные объекты `Product`, входные списки не изменяются.
Обычного цикла достаточно: он не создаёт промежуточных списков и позволяет
остановиться при достижении лимита.

## Сложность

`p` — размер каталога, `r` — число рекомендаций, `e` — число исключений,
`k` — число товаров в результате, `k ≤ min(p, r)`.

Для основной функции ожидаемое время — `O(p + e + r)`: построение индекса,
множества исключений и один обход рекомендаций.
Дополнительная память без результата — `O(p + e)`: индекс, исключения и
не более `k` добавленных идентификаторов. Результат занимает `O(k)` памяти.

Оценки предполагают обычное распределение хешей и ожидаемую `O(1)` стоимость
поиска и добавления в хеш-таблицы. Время секундомером не измеряется.

## Продолжение

`ProductSelector` строит индекс один раз при создании.
`loadCatalog` заменяет его индексом нового каталога, включая новые значения полей.
Изменение переданного списка само по себе индекс не обновляет.
Исключения, добавленные идентификаторы и результат создаются заново для каждого
запроса, поэтому запросы независимы.

```kotlin
val selector = ProductSelector(products)
val first = selector.select(recommendedIds, excludedIds, limit = 1)
val next = selector.select(otherRecommendedIds, emptyList(), limit = 10)
selector.loadCatalog(newProducts)
val updated = selector.select(recommendedIds, excludedIds, limit = 10)
```

Подготовка каталога: ожидаемое время `O(p)`, память `O(p)`.
Для одного запроса пусть `s ≤ r` — число просмотренных рекомендаций.
Ожидаемое время запроса — `O(e + s)`, дополнительная память без результата —
`O(e + k)`, память результата — `O(k)`. Общий индекс занимает `O(p)` отдельно.
При перезагрузке строится новый индекс; старый затем может освободить сборщик мусора.

Просмотр прекращается сразу после добавления `limit` товаров или в конце списка.
Число `s` зависит от расположения подходящих товаров, повторов и исключений.
При `limit = 0` рекомендации не читаются: время и память запроса — `O(1)`.

## Тесты

[ProductSelectionTest.kt](src/test/kotlin/lab2/ProductSelectionTest.kt) сохраняет
два начальных теста и проверяет другой порядок каталога, повторы рекомендаций и
исключений, неизвестные и недоступные товары, пустые входы, отсутствие подходящих
товаров, сохранность входов и независимость вызовов.

[ProductSelectorTest.kt](src/test/kotlin/lab2/ProductSelectorTest.kt) проверяет
нулевой лимит, лимит 1, досрочное завершение, нехватку подходящих товаров,
независимость запросов, сохранность входов, замену каталога и пустой каталог.
Ожидаемые списки заданы явно и сравниваются целиком.

Для подсчёта чтений используется тестовый `CountingList`: его `get` считает
полученные элементы, сохраняя их значения и порядок. В тесте
`stopsReadingRecommendationsAsSoonAsLimitIsReached` рекомендации —
`[99, 2, 1, 3, 3, 4, 1]`, исключения — `[1, 1, 100]`, товар 2 недоступен.
При лимите 2 результат — Monitor и Webcam; прочитаны 6 из 7 рекомендаций.
При нулевом лимите прочитано 0. Счётчик не входит в рабочую реализацию
и не является измерением времени.
